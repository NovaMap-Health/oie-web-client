# OIE Web Client 1.1.0

OIE Web Client 1.1.0 improves channel editing, message browsing, scripting,
permissions and first-login recovery for Open Integration Engine 4.6.0.
This release includes the changes planned for the unpublished 1.0.2 release.

## Changes since 1.0.1

- Preserve connector edits, exact channel tag names, typed Delimited Text column
  lists, fixed-width settings and Velocity expressions when editing and saving.
  Match Swing's connector-switch confirmations, destination mappings and
  Database Reader/Writer driver validation. Highlight missing required fields
  consistently, and include destination response datatypes and ACK validation
  in Set Data Types.
- Add searchable message-template editors and the transformer's Generated Script
  preview. Keep Monaco menus and tooltips visible, scope completions to their
  requesting editor, retry code-template loading, and let plugins contribute
  Reference lists and autocomplete entries.
- Populate the source Response dropdown from channel response variables,
  including installed rule and step providers through Web Support 1.1.0.
- Open message content containing XML-forbidden control characters. Preserve
  source-message browsing context, remember custom metadata search keys per
  channel, and match Swing's page-size controls and defaults.
- Enforce permissions across navigation, direct URLs, commands and Data Pruner.
  Display access-denied states for restricted built-in pages and support
  authorization-dependent plugin availability through framework API 4.9.0.
- Recover first-login setup after partial saves, align password workflows with
  Swing, protect unsaved new channels, and recover from lost drafts.
- Revalidate password changes in Edit User and Edit Account after an uncertain
  replacement-password response, so retries cannot report success while leaving
  a different password saved on the engine.
- Refresh dashboard status on entry, improve related command-palette results,
  preserve cleared server logs with an explicit Reset action, and honor
  customized navigation labels in page headings.
- Patch production dependency advisories and serve bundled webfonts under the
  existing `font-src 'self'` policy.

## Compatibility and companion release

The supported engine is **OIE 4.6.0**. Source and packaged Node deployments
require Node.js 22.18 or newer; CI uses 22.22.3. Docker images support amd64 and
arm64. The WAR runs in the engine's embedded web server.

Use the coordinated **Web Support 1.1.0** extension for the embedded client,
message-tree serialization, engine-side JavaScript validation, engine-served
plugin UIs, extension datatype vocabulary descriptions and custom response
variable discovery. The base Node/Docker administrator also works without Web
Support; companion-dependent features require its endpoints.

Extensions opt into message-tree descriptions by declaring their SHARED
`MessageVocabulary` class in `webadmin/plugin.json`. Built-in vocabularies
remain authoritative; missing or invalid declarations keep bare labels.
See the [Web Support documentation](https://github.com/gibson9583/oie-web-support-plugin#readme).

The web framework contract is **4.9.0**, separate from the client and engine
versions. Plugins using Reference/autocomplete registration need `oie.apiMin`
4.8; plugins using command availability or required authorization providers need
4.9. See the [plugin API compatibility guide](https://github.com/gibson9583/oie-web-client/blob/v1.1.0/web-administrator/PLUGINS.md#api-version-compatibility).

The automatic Web Support pipeline builds the OIE 4.6.0 package. The separately
published 1.0.5 compatibility package for OIE 4.5.2 does not establish 4.5.2
support for this release.

For installations using the Role-Based Access Control extension, upgrade to
[RBAC 1.1.4](https://github.com/diridium-com/role-based-access-control/releases/tag/v1.1.4)
alongside Web Client 1.1.0. It declares the authorization provider and the scoped
Data Pruner permissions used by this client; earlier versions do not supply
the complete permission vocabulary.

## Upgrade notes

**Existing File channels:** Upgrading does not rewrite stored channels. A
successful classic-editor or wizard save repairs FTP/WebDAV channels saved by
1.0.0 or 1.0.1 with Anonymous enabled and both credentials blank, setting both
username and password to `anonymous`. Redeploy deployed channels to use the
repair. Ordinary saves preserve custom anonymous credentials; explicitly
toggling Anonymous or changing the scheme can reapply scheme defaults. Clone,
JSON import, XML import and group import preserve the imported values, so an
affected channel still needs an editor or wizard save. For SFTP/SMB, a stale
Anonymous flag no longer bypasses credential validation; a successful save
clears the flag while preserving named credentials. SFTP public-key-only
authentication does not require a password.

**Delimited Text channels:** Existing settings retain their engine-typed arrays
through edits and saves. Columns discarded by earlier client versions cannot be
recovered automatically.

**Plugin message-detail consumers:** `api.messages.get` now parses engine XML
directly. Numeric-looking fields without an explicit model/type conversion,
including `message.receivedDate.time` and connector-message calendar `time`, are
strings. Convert fields explicitly when arithmetic or date construction requires
it, for example `Number(message.receivedDate.time)`. Known message IDs/counters
still become numbers when safe, model `processed`/`encrypted` fields remain
booleans, and explicitly typed map/list primitives retain their conversions.
Payload text and untyped scalar metadata remain text, including `000123` and
`false`; a nonempty string is truthy in JavaScript.

Parsed message-detail records and map objects have no object prototype; arrays
remain ordinary arrays. Use `Object.hasOwn(record, key)` rather than calling
`record.hasOwnProperty(key)` or depending on inherited object methods.

The separate engine XML-to-JSON encoding failure on Windows-1252 configurations
is not fixed by this client release.

## Deployment artifacts

- `oie-webadmin.war`: deploy into OIE's `webapps/` directory, or install the
  coordinated Web Support package to manage its embedded WAR.
- `oie-webadmin-node.tar.gz`: prebuilt standalone runtime. Extract it, run
  `npm ci --omit=dev` at its root, configure the engine connection, then start
  with `node web-administrator/server/index.js`.
- `gibson9583/oie-web-client:1.1.0`: Docker image; configure the engine connection
  using the documented environment variables or mounted configuration.
- The two archive assets have `.sha256` companions; `release-receipt.json`
  records their hashes and the source commit.

Engine TLS verification is enabled by default in Node and Docker deployments.
Trust private/self-signed engine CAs through `NODE_EXTRA_CA_CERTS` and use a
matching engine hostname. Install or upgrade Web Support, restart OIE, and open
`https://<oie-host>:8443/oie-webadmin/` for its embedded client.
